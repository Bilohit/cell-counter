Hover feel — two picks to make

Pick one variant in each section. Only the pick gets built into the app; the other three are thrown away. Hover each tile and each slider with the mouse, in both themes, and choose on feel — every variant carries the same capture name, the same count and the same placeholder thumbnail, so the only difference you can see is the motion.

Variant A is what the app does today, reproduced from the shipped code. B, C and D each carry exactly one idea, and every one of them animates only cheap properties — transform, opacity, box-shadow — so nothing here can cost a layout pass on a wall of thirty cards.

1 — Gallery tile hover

Honest note on A: today's tile does not snap. It already animates — a 3 px lift with a growing shadow over 260 ms, and the image pushing in over 420 ms on the same curve. What A is, is a combination: two durations, a lift, a shadow, a hairline colour change and a scale, all at once. B, C and D each keep one of those and drop the rest.

Reduced motion. Under @media (prefers-reduced-motion: reduce) every added transform in B, C and D is dropped and all transition durations collapse to .01ms, so all four variants degrade to the same instant state change — the same rule web/src/index.css already ships globally. Turn the OS setting on and re-open this file to check it.

Hairlines. Every rounded box on this page, in every state, carries border: 1px solid transparent plus box-shadow: inset 0 0 0 1px <colour> — never a coloured CSS border. That is the 2026-09-19 Gecko/WebRender seam rule, and each hovered state re-states its inset ring rather than inheriting it, because a box-shadow list is replaced wholesale, not merged.

Standalone. No build step, no framework, no CDN, no network. Token values are copied by value out of web/src/index.css; the thumbnail is CSS gradients, not a file from data/. Nothing here imports from or affects the app.
